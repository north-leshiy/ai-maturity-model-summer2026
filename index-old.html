Матрица зрелости AI в SDLC 2026

Пять уровней: от чата до автономности

Ур. Название Суть Ось автономности
L0 Без AI Команда работает без AI-инструментов —
L1 Чат ChatGPT / Claude web, copy-paste, нет связи с кодом ▪
L2 Локальный агент Агент в IDE/терминале, активная сессия, HITL на каждом шаге ▪▪
L3 AI Native Background-агент, sandbox, evals, HITL только на PR ▪▪▪
L4 Полная автономность Агенты инициируют сами, работают между системами, оркестрация ▪▪▪▪

Главная ось — автономность. Пересекается с инфраструктурным слоем.

L0 и L1: откуда приходят

L0 — Без AI

  • Осознанный выбор или инерция
  • Иногда продиктован регуляторными ограничениями
  • Отставание нарастает быстро

L1 — Чат

  • ChatGPT/Claude web вне IDE
  • Контекст теряется после сессии
  • Много ручной работы copy-paste
  • Точка входа для большинства команд
В 2026 автокомплит (Copilot, Codeium) — уже не уровень, это гигиена.
Он растворился внутри L1 → L2.

L2 / Assist
Агент на машине разработчика

L2 Суть

  • Агент запускается в IDE/терминале, работает в активной сессии
  • HITL на входе (постановка) и выходе (review каждого изменения)
  • Гранулярность: файл, функция, локальная задача
  • Один человек — одна машина — максимум несколько задач в момент

Что работает устойчиво

  • Эксплоративная отладка
  • Рефакторинг под надзором
  • Прототипирование и парное программирование
  • Делегирование задач на 1–3 часа

Когда L2 — стратегия

  • Соло-разработчики, малые команды
  • Нет готовности к инфраструктурным инвестициям
  • Нет команды для поддержки runtime

L2 Гвозди, которые блокируют переход на L3

  • Vendor-specific форматы промптов и плагинов — не выносятся в централизованный runtime
  • Контекст живёт в головах и личных файлах вместо общего SDD
  • Доступы и секреты привязаны к учётке разработчика, а не к роли
  • «Каждый цех — свой контекст, свой стек» — фрагментация инфраструктуры
Эти решения кажутся локальными. Но именно они делают переход на L3
революцией, а не эволюцией.

L3 / Delegate
Задача делегируется агенту целиком

L3 Суть

  • Background-агенты в централизованном runtime, вне сессии человека
  • HITL только на финальной проверке: PR review, approval
  • Гранулярность: тикет, баг, мелкая фича
  • Длительность: часы, ночи, выходные; параллельно — десятки задач

Что становится возможным

  • Bulk-разгребание Sentry без участия разработчика
  • Dependency updates по расписанию
  • Alert → fix attempt → PR без человека
  • Self-service для PM / QA / Support

Целевая метрика L3

70%

задач доходят до PR
без HITL внутри потока

Уже в конце 2025 были компании с такими показателями

L3 Инфраструктурный минимум

Без этого L3 не существует — есть только фасад

⚙️ Agent runtime — K8s / serverless / собственная платформа
🔒 Sandbox — read prod / write staging / политики без секретов
🔑 Secrets as a service — доступы к роли, не к человеку
📊 Телеметрия — Langfuse / OpenTelemetry, сквозная трассировка
✅ Evals — golden set + онлайн-метрики + регрессии агентов
🛡️ Guardrails — политики, PII, rate limits, бюджеты на задачу
📨 Очереди и триггеры — Sentry → задача, Jira → задача, webhook → задача
📝 SDD — сквозной источник контекста для всех агентов команды
🔄 Версионирование — агенты и промпты как код, релизный цикл

L3 Anti-patterns: «L3 с фасадом»

Самое опасное — выглядит как L3, работает как хаос:

  • Background-агенты без evals — автономно ломают прод
  • Sandbox на честном слове — инцидент с доступами — вопрос времени
  • Каждый отдел строит свой runtime — фрагментация × N
  • SDD у каждого свой — агенты разных команд несовместимы по контексту
  • Нет учёта затрат — бюджет у LLM-провайдера удваивается без объяснения
Guardrails и evals — критическая инфраструктура.
Не важно, на каком вы уровне: без них вы строите на песке.

Стоимость: L2 vs L3

Параметр L2 L3
LLM-расходы Подписка ($20–$100 / чел) API + runtime (растут с задачами)
Инфра Ноутбук разработчика K8s / serverless + мониторинг
Команда Не нужна Нужна платформенная команда
Параллелизм 1–3 задачи / человек Десятки задач одновременно
Демпинговые подписки на Claude / Codex — временное окно.
Рано или поздно их зажмут или накроет регулятор.
Если вы на своих open-source моделях — разницы стоимости L2 vs L3 почти нет.

SDD — сквозная инфраструктура, не инструмент цеха

SDD (Software Design Document / System Design Doc) — это единый источник контекста для всех агентов команды.

  • Без общего SDD каждый цех плодит своё «облако контекста»
  • Агенты фронта и бэка не понимают контекст друг друга
  • Масштабировать в крупной компании — нетривиально
SDD — это не документация. Это инфраструктурный слой.
Он должен быть сквозным и единым для всей команды.

Коллега из Сбербанка расскажет об этом подробнее — внедрение SDD в компанию такого масштаба весьма непросто.

L4 / Autonomous
Агенты инициируют и работают между системами

L4 Суть

  • Агенты сами инициируют работу по событиям и бизнес-метрикам
  • Декомпозируют задачи, делегируют sub-агентам, синхронизируются
  • HITL только по эскалации — агент сам решает, когда звать человека
  • Периметр: CRM, биллинг, мониторинг, документация, аналитика

Путь 1: Кастомные агенты

  • Вертикальные агенты через A2A
  • Параллельный поток производства
  • Строится с нуля, рядом с текущим процессом

Путь 2: Эволюция L3

  • Универсальные кодовые агенты L3
  • Обёрнуты оркестрацией (LangGraph, Temporal)
  • Дешевле и эволюционнее

Можно сочетать: кастомные агенты — на доменных задачах, универсальные — на кодовых.

L4 Вызовы и референсы

Главные вызовы

  • Sandboxing межсистемных действий — потолок доверия
  • Evals на длинных цепочках — комбинаторный взрыв
  • Доверие команды и регуляторов — узкое место, не технологическое

Чем вдохновляться

  • GitLab Duo Agents (EE) — agent as a feature
  • GitHub Agent HQ — оркестрация как первичная сущность
  • JetBrains Central — каталог агентов в IDE
  • Atlassian Rovo — агенты как роли в коллаборации
Инфраструктура L4 = L3 + оркестратор с длинной памятью + A2A-протокол + policy engine + multi-agent observability

Как двигаться вперёд

L2 и L3 можно строить параллельно

  • Большинство из нас уже делают это
  • L2 даёт немедленную отдачу, L3 — масштаб и автономность
  • Важно думать стратегически: переход L3 → L4 закладывается сейчас

Остановиться на L2 — это выбор

  • Соло / малая команда
  • Нет инфра-ресурсов
  • Стратегический выбор с осознанными трейдоффами

Горизонт — L3/L4?

  • Архитектурные решения сейчас определяют: эволюция или революция
  • Гвозди L2 делают переход болезненным
  • Начните с инфра-минимума L3

С чего начать L3: мелкие задачи

Не обязательно стартовать с крупных эпиков:

  • Review-агент — это уже часть L3 (облачный runtime, без сессии человека)
  • Sentry-разгребание — агент разбирает беклог мелких ошибок, создаёт PR
  • Dependency updates по расписанию — patch-версии без участия человека
  • Security patches — автоматический апдейт и PR на проверку
Коллеги разгребли огромный технический долг в Sentry,
запустив отладку background-агентами за выходные.

Стратегический тезис

  • L4 не достигается экспромтом — он закладывается архитектурно на L3
  • Если ваш потолок — L2, можно остановиться сознательно
  • Если горизонт — L3/L4, решения сейчас определяют: эволюция или переписывание

Не тратьте время на

  • Vendor-lock инструменты без API
  • «Свой» SDD в каждом цехе
  • Секреты в среде разработчика

Инвестируйте в

  • Общий SDD как инфраструктуру
  • Secrets as a service
  • Централизованные evals и телеметрию
