Зачем нужна модель зрелости?

Что такое модель зрелости?

  • Фреймворк для оценки текущего состояния
  • Понятные уровни развития (от хаоса к совершенству)
  • Референсные точки: "где мы" и "куда идём"
  • Roadmap для развития

Примеры моделей зрелости

  • Kanban Maturity Model — 6 уровней организационной зрелости
  • DevOps Maturity Model — от ручного деплоя до GitOps
  • CMMI — Capability Maturity Model Integration
  • Technology Radar (ThoughtWorks) — Adopt/Trial/Assess/Hold
  • Data Management Maturity — от Excel до Data Mesh

Мы научились оценивать...

  • Процессы разработки (Agile, DevOps)
  • Качество кода (статический анализ, code review)
  • Инфраструктуру (IaC, observability)
  • Команды (performance reviews, OKR)

А как оценить зрелость внедрения AI?

Зачем модель зрелости в AI?

Проблема #1: Скорость изменений

  • Технологии и инструменты меняются каждый месяц
  • GPT-3 → GPT-4 → Claude → Gemini → локальные модели
  • Copilot → Cursor → Claude Code → Devin → ...
  • То, что работало вчера — устарело сегодня

Проблема #2: Непонятно что работает

  • Какие практики реально дают результат?
  • Много хайпа, мало проверенных кейсов
  • Сложно отделить маркетинг от реальной пользы

Проблема #3: Нужны референсы

Модель зрелости подразумевает:

  • Есть компании на каждом уровне
  • Можно смотреть на лидеров как на референс
  • Понятен путь от уровня к уровню
  • Не нужно изобретать велосипед

Проблема #4: Где я сейчас?

  • Понять текущий уровень развития
  • Построить roadmap до следующего уровня
  • Определить конкретные шаги
  • Измерить прогресс

Открытые вопросы: метрики, бенчмарки, best practices

Какой этап разработки автоматизировать?

Этапы разработки и AI

  • Анализ требований — генерация user stories, acceptance criteria
  • Проектирование — архитектурные решения, API design
  • Кодирование — автокомплит, генерация кода, рефакторинг
  • Code Review — автоматический анализ, suggestions
  • Тестирование — генерация тестов, test data
  • Документация — генерация docs, комментарии
  • DevOps — IaC, troubleshooting, observability

Обзор моделей зрелости AI

Gartner AI Maturity Model

  1. Awareness — знаем что AI существует
  2. Active — эксперименты, пилоты
  3. Operational — AI в продакшене
  4. Systemic — AI интегрирован в процессы
  5. Transformational — AI меняет бизнес-модель

*Фокус на бизнес-трансформации

Stanford HAI Framework

  1. Exploring — изучение возможностей
  2. Experimenting — пилотные проекты
  3. Formalizing — стандарты и governance
  4. Optimizing — масштабирование и оптимизация
  5. Transforming — AI-first организация

*Академический подход, фокус на governance

Разработчико-центристская модель

  1. Level 0 — Не используют AI вообще
  2. Level 1 — ChatGPT в браузере, copy-paste
  3. Level 2 — IDE-интеграция (Copilot, Cursor)
  4. Level 3 — AI-агенты в workflow (Claude Code, Aider)
  5. Level 4 — Автономные агенты, CI/CD интеграция
  6. Level 5 — AI-first разработка, vibe coding

Проблемы на каждом этапе

  • Level 1→2: Лицензии, безопасность данных, обучение
  • Level 2→3: Изменение процессов, доверие к AI
  • Level 3→4: Инфраструктура, автоматизация, контроль качества
  • Level 4→5: Культура, метрики, переосмысление ролей

На каждом переходе — свои барьеры!

Типичные проблемы перехода

  • Безопасность: утечка кода, секреты в промптах
  • Качество: галлюцинации, неоптимальный код
  • Процессы: code review AI-кода, ответственность
  • Культура: сопротивление, страх замены
  • Метрики: как измерить пользу?
